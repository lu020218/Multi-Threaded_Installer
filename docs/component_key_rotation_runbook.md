# 组件签名密钥轮换 Runbook

适用范围：`component_manifest.yaml` 使用 Ed25519 签名校验的发布流程。  
目标：在不中断安装能力的前提下安全轮换发布密钥。

## 1. 约定

- 每个发布密钥有唯一 `key_id`，例如：`release-2026q1`
- 组件元数据签名字段为 `components[].package.signature`（Base64）
- 清单中声明 `public_key_id`
- 安装端通过环境变量加载公钥：
  - `MTI_COMPONENT_PUBLIC_KEYS=key1=base64pubkey;key2=base64pubkey`

## 2. 标准轮换步骤

1. 生成新密钥对（离线环境）
2. 将新公钥加入发布系统，并分配新 `key_id`
3. 安装端灰度下发“多公钥配置”（旧+新同时存在）
4. 使用新私钥签发组件，清单切换 `public_key_id` 到新 `key_id`
5. 观察一个发布周期（建议 >= 1 个完整版本窗口）
6. 移除旧私钥（立即），旧公钥（延迟移除）

## 3. 回滚策略

- 若新密钥签名发布出现异常：
  - 立即切回旧 `public_key_id` 和旧签名产物
  - 安装端保留旧公钥可直接继续安装
- 不要在同一窗口同时撤销旧公钥与切新签名

## 4. 安全要求

- 私钥必须离线保管，严禁进入仓库
- CI 仅可读取签名后的产物，不可持有私钥
- 公钥配置变更需双人复核
- 记录轮换审计：时间、操作者、key_id、影响版本范围

## 5. 发布检查项

- [ ] 新 key_id 已登记
- [ ] 安装端已下发旧+新公钥
- [ ] 新组件签名可通过校验
- [ ] 回滚到旧 key_id 流程已演练
