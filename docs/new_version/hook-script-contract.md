# 安装脚本契约（pre/post bat）— 项目组基线

约定 `packager.yaml` 中 `hooks.preInstall` / `hooks.postInstall` 两个脚本的行为。
引擎实现与脚本作者都以本文件为准。

## 1. 配置字段

| 字段 | 含义 | 取值 |
|------|------|------|
| `path` | 脚本路径，相对 `--config` 目录解析 | 字符串 |
| `args` | 本次构建特有的额外参数 | 字符串，可为空 |
| `onFailure` | 失败时的处理 | `abort` \| `continue` |
| `timeoutSec` | 超时上限（秒） | 整数 |

## 2. 成功 / 失败判据（引擎写死，不可配）

- 退出码 `0` = 成功。
- 退出码 非 0 = 失败。
- **超时**：到达 `timeoutSec` 后引擎 kill 进程，**一律按失败处理**，走 `onFailure`。

## 3. onFailure 语义

- `abort`：中止安装并回滚。用于“这步不成功，装了也是坏的”。
- `continue`：记录日志后继续。用于可选的、失败也不影响主体安装的步骤。

## 4. 注入变量

脚本运行时可直接读取以下环境变量：

**引擎注入**（引擎才知道的值）
- `INSTALL_DIR` — 实际安装目录
- `VERSION` — 本次安装的版本号

**系统现有**（引擎只保证不清空环境块，无需注入）
- `USERPROFILE`、`APPDATA`、`LOCALAPPDATA`、`ProgramData` 等

注入方式为**环境变量**，不拼进命令行。脚本应优先读环境变量，
`args` 只承载本次构建特有的额外参数，避免漏写参数导致脚本拿不到路径。

## 5. 路径与执行

- **打包期**：`path` 相对 `--config` 目录解析，脚本被读入并内嵌进安装器。
- **运行期**：安装器从临时释放目录（或内存）读取后执行，
  与终端用户机器上是否存在该路径无关。

## 6. 权限

脚本继承安装器的管理员权限运行，**脚本内不要再自行 elevate**。

## 7. 职责边界（重要）

这两个 bat **只做本次构建特有、与版本演进无关的收尾动作**
（如注册本次才有的服务、拷贝许可文件等）。

**跨版本兼容一律走引擎内的迁移函数**，禁止写进 pre/post bat。
否则兼容逻辑会散落、与版本对不上，丧失“迁移跟版本走、该删随版本删”的好处。
