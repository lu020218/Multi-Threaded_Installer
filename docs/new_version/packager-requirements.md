# 打包安装器 需求文档

内部项目组自用的 Windows 打包安装器。本文档记录经讨论对齐的设计原则、
`packager.yaml` 配置规格、安装脚本契约，以及安装引擎职责（含跨版本兼容机制）。

---

## 1. 背景与目标

项目组维护单一产品的 Windows 安装器，希望通过一份配置文件驱动打包，
同时保留对特殊场景（如旧版本兼容）的处理能力。

早期尝试用一份“通用” YAML 覆盖所有可配项，导致两个问题：配置项过多、
改起来负担重；同时仍有大量场景不得不改引擎 C++ 代码。根因是**值与逻辑被错配**——
稳定的值做成了过度灵活的配置，而演进的逻辑被硬塞进配置却表达不了。

本设计的目标：**让值与逻辑各归其位**，使配置稳定精简、逻辑随版本演进。

---

## 2. 核心设计原则

### 2.1 划分标准

一项内容放在哪里，由两个问题决定：

1. 它的值会不会**因构建而变**？
2. 改它**要不要重新编译引擎**？

> **会因构建而变、且改它不需要重编引擎 → 放 YAML。否则 → 放引擎 C++。**

### 2.2 三层职责

| 层 | 职责 | 改动代价 |
|----|------|----------|
| **YAML** | 声明“本次构建是什么 + 怎么打包 + 跑哪两个 bat” | 改完直接打包，无需重编 |
| **bat 脚本** | 本次构建特有、与版本演进无关的收尾动作 | 改脚本即可 |
| **C++ 引擎** | 所有稳定机制 + 跨版本兼容迁移 | 改动需重编引擎，随版本走 |

### 2.3 内部项目的取舍

作为内部自用工具（非商业软件、只服务单一产品），不为“万一别的产品要不同的值”
保留配置项。**配置项不是免费的，每多一个可配点就多一个要记、要对、可能配错的地方。**
凡是只有一个产品在用、值几乎不变的，一律在引擎里写死；真出现第二种取值时，
再把那一项单独提回 YAML（成本仅数分钟）。

### 2.4 兼容逻辑不进配置

跨版本兼容是**随版本演进的逻辑**，不是一组稳定的值，配置无法表达
（往往需要“读旧状态 → 判断 → 分支”）。它必须放在引擎内、跟版本走、
该淘汰时随版本删除。**严禁**用 YAML 的 legacy 名单或 bat 脚本承载兼容逻辑。

## 3. `packager.yaml` 配置规格

### 3.1 打包命令

```
.\packager.exe --input input --config config --output output/MyTestApp_Setup.exe
```

- `--input`：payload 来源根目录。
- `--config`：配置目录，`packager.yaml` 及其引用的相对路径（icon、脚本）以此为基准。
- `--output`：生成的安装器 exe 路径。

### 3.2 配置项

#### app —— 本次构建的身份与取值

| 字段 | 含义 | 说明 |
|------|------|------|
| `productName` | 用户可见产品名 | |
| `publisher` | 发布者/公司名 | 同时用作版本资源的 CompanyName，不单列 companyName |
| `version` | 版本号 | 每次发版必改 |
| `defaultDir` | GUI 默认安装目录 | 支持 `%ProgramFiles%` 等环境变量 |
| `icon` | 安装器 exe 图标 | 路径相对 `--config` 目录解析 |
| `copyright` | 版权声明 | 可配；缺省时引擎用 publisher + 构建年份生成 |

#### package —— 打包基础参数

| 字段 | 含义 | 取值 |
|------|------|------|
| `compression.algorithm` | 压缩算法 | `xz` \| `zstd` \| `none` |
| `compression.level` | 压缩级别 | 整数，有效范围由算法决定 |

#### hooks —— 安装前/后脚本

`preInstall` 与 `postInstall` 各含以下字段：

| 字段 | 含义 | 取值 |
|------|------|------|
| `path` | 脚本路径，相对 `--config` 目录解析 | 字符串 |
| `args` | 本次构建特有的额外参数 | 字符串，可为空 |
| `onFailure` | 失败处理 | `abort` \| `continue` |
| `timeoutSec` | 超时上限（秒） | 整数 |

### 3.3 配置示例

```yaml
app:
  productName: Weclaw Desktop
  publisher: MyCompany
  version: 7.0.0-beta1
  defaultDir: "%ProgramFiles%\\Weclaw Desktop"
  icon: app.ico
  copyright: "Copyright (c) 2026 MyCompany"

package:
  compression:
    algorithm: xz
    level: 9

hooks:
  preInstall:
    path: scripts/pre_install.bat
    args: ""
    onFailure: abort
    timeoutSec: 300
  postInstall:
    path: scripts/post_install.bat
    args: ""
    onFailure: continue
    timeoutSec: 600
```

## 4. 安装脚本契约（pre/post bat）

引擎实现与脚本作者均以本节为准。

### 4.1 成功 / 失败判据（引擎写死，不可配）

- 退出码 `0` = 成功；非 `0` = 失败。
- 超时：到达 `timeoutSec` 后引擎 kill 进程，**一律按失败处理**，走 `onFailure`。

### 4.2 onFailure 语义

- `abort`：中止安装并回滚。用于“这步不成功，装了也是坏的”。
- `continue`：记录日志后继续。用于失败也不影响主体安装的可选步骤。

### 4.3 注入变量

脚本运行时可直接读取以下环境变量：

- **引擎注入**（引擎才知道的值）：`INSTALL_DIR`、`VERSION`
- **系统现有**（引擎只保证不清空环境块，无需注入）：
  `USERPROFILE`、`APPDATA`、`LOCALAPPDATA`、`ProgramData` 等

注入方式为**环境变量**，不拼进命令行。脚本应优先读环境变量；
`args` 仅承载本次构建特有的额外参数，避免漏写参数导致脚本拿不到路径。

### 4.4 路径与执行

- **打包期**：`path` 相对 `--config` 目录解析，脚本被读入并内嵌进安装器。
- **运行期**：安装器从临时释放目录（或内存）读取后执行，
  与终端用户机器上是否存在该路径无关。

### 4.5 权限

脚本继承安装器的管理员权限运行，**脚本内不要再自行 elevate**。

### 4.6 职责边界

这两个 bat **只做本次构建特有、与版本演进无关的收尾动作**
（如注册本次才有的服务、拷贝许可文件等）。**跨版本兼容一律走引擎迁移**（见第 6 节）。

## 5. 引擎写死的默认值与约定

以下内容不在 YAML 暴露，由引擎固定处理。如某项将来确需按构建变化，再单独提回 YAML。

- **版本资源**：CompanyName 取 `publisher`；FileVersion/ProductVersion 由 `version`
  生成（自动去掉 `-beta` 等预发布后缀，满足 Windows 版本资源的纯数字要求）；
  copyright 缺省由 publisher + 构建年份生成。
- **数据目录**：统一使用产品名，避免多种写法并存。
- **状态持久化**：固定一处注册表 + 一个 `install-state.json`，路径在引擎内拼接。
- **UI**：页面结构与“勾选框↔组件”绑定由 skin 承载，引擎固定加载。
- **安装行为默认值**：requireAdmin、minWindows、互斥量名、大文件阈值、
  默认语言、是否开机自启/桌面快捷方式等，按固定默认处理。

> 注：上述默认值的具体取值由引擎实现确定，本文档不固化，以免与代码漂移。

## 6. 跨版本兼容机制（引擎内）

### 6.1 形态

兼容迁移作为引擎内的一组 C++ 函数（迁移表），与引擎一同编译，**不引入任何外部
运行时**（不打包 Python/Node 等解释器，避免体积负担）。每个迁移对应一个版本节点。

### 6.2 执行规则（引擎写死）

安装/升级时，引擎读取已安装版本，将**版本号高于已安装版本**的迁移
**按版本顺序依次执行**，执行完成即记录。

### 6.3 迁移内容由代码决定

“怎么迁”完全在迁移函数内实现，可自由进行条件判断、读取旧注册表/旧路径后再决策、
按版本分支等——这正是配置无法表达、必须用代码的部分。

典型场景：
- 程序名变更但注册表键/安装路径名未变 → 仅收尾名字残留（快捷方式、卸载项 DisplayName），
  **不动任何路径**。
- 到某版本节点路径名也变更 → 在该版本的迁移中实现目录迁移与路径型注册表值重写。

### 6.4 生命周期

某旧版本不再有用户时，将对应迁移函数连同其历史一并删除。
迁移代码与引擎同寿命、跟版本走，因此不会像配置里的 legacy 名单那样越积越多、无人敢删。

---

## 7. 交付物

- `packager.yaml` —— 配置文件（见第 3 节规格）。
- `scripts/pre_install.bat`、`scripts/post_install.bat` —— 安装脚本（遵循第 4 节契约）。
- 安装引擎（C++）—— 实现第 4、5、6 节的机制与约定。
- 本需求文档 + 脚本契约说明，作为项目组基线。
