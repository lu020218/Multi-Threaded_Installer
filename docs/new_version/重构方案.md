# 打包安装器重构方案（值/逻辑归位）

> 配套文档：[packager-requirements.md](packager-requirements.md)、[hook-script-contract.md](hook-script-contract.md)、[packager.yaml](packager.yaml)
>
> 本方案落实需求文档第 2 节"值与逻辑各归其位"的原则，采用**激进式一次性切换**：
> 删除旧 YAML 的全部冗余字段及其对应 C++ 逻辑，把稳定值写死进引擎，把跨版本兼容
> 改造成引擎内迁移函数表。**不保留旧 schema 兼容解析。**

---

## 1. 目标与范围

| 维度 | 当前（schemaVersion 2/3） | 目标 |
|------|--------------------------|------|
| YAML 区块 | `app / package / install / ui / layout / lifecycle`（≈370 行） | 仅 `app / package / hooks`（≈40 行） |
| 组件机制 | `layout.components`（embedded/local/download + bat） | 删除；可选收尾改走 `hooks` 的 pre/post bat |
| 清理/legacy | `lifecycle.cleanup.onUpgrade/onUninstall`（YAML 名单） | 删除；卸载清理引擎写死，升级兼容走**迁移函数表** |
| 版本资源 | `app.product.*` 全字段手填 | 引擎从 `version`/`publisher` 派生 |
| 跨版本兼容 | YAML legacy 名单 + 散落逻辑 | 引擎内 C++ 迁移表（随版本走，可删） |

范围：`packager`、`common`（config_types / manifest / archive_types）、`installer`、`uninstaller`、`gui` 五个模块，外加新增 `migration` 子模块。

## 2. 当前架构与数据流

```
构建期 (packager.exe)
  packager.yaml
    └─ ConfigurationLoader::loadConfiguration            src/packager/configuration_loader.cpp
        └─ PackagerConfiguration                         include/common/config_types.h
            └─ PackageManifestBuilder                    src/packager/package_manifest_builder.cpp
                └─ PackageManifest                       include/common/package_manifest.h
                    └─ (codec) ExtendedInstallationMetadata
                        └─ 嵌入安装器 exe 资源

运行期 (installer.exe / uninstaller.exe)
  embedded ExtendedInstallationMetadata                  include/common/archive_types.h:97
    └─ MetadataParser                                    src/installer/metadata_parser.cpp
        └─ ExecuteInstallService(options, metadata...)   src/installer/install_service.cpp
            └─ 安装/清理/注册表/快捷方式/卸载入口…
  GUI 绑定亦从 metadata 读 ui.componentSelection 等       src/gui/gui_component_binding.cpp
```

**核心问题**：`ExtendedInstallationMetadata` 是构建期→运行期唯一的桥，目前它携带了
`installerCleanup / uninstallerCleanup / installState / installInfo / systemUninstallEntry /
layoutComponents / uiComponentSelection / lifecycleUpgradeCleanup / lifecycleInstallRegistry`
等**稳定值与兼容逻辑**。重构就是把这座桥收窄到只剩"身份 + 载荷 + 钩子"。

## 3. 新架构：三层职责落到代码

| 层 | 代码位置 | 承载内容 |
|----|---------|---------|
| **YAML** | `packager.yaml` | `app`(productName/publisher/version/defaultDir/icon/copyright?) · `package.compression`(algorithm/level) · `hooks`(preInstall/postInstall) |
| **bat** | 打包时内嵌、运行时临时释放执行 | 本次构建特有的收尾动作；引擎注入 `INSTALL_DIR`/`VERSION` 环境变量 |
| **C++ 引擎** | `installer`/`uninstaller`/新增 `migration` | 全部稳定机制 + 写死默认值 + 跨版本迁移表 |

新的构建期→运行期桥（收窄后的 `PackageManifest`）只剩四块：

```
PackageManifest（重构后）
  ├─ identity      productName / publisher / version / copyright（可空，引擎派生）
  ├─ payload       压缩算法 + 各 folder 的 offset/size/checksum/fileIndex（单产品单载荷）
  ├─ hooks         preInstall/postInstall：脚本内容(内嵌) + args + onFailure + timeoutSec
  └─ packVersion   manifest 二进制版本号（codec 用）
```

> icon 不入 manifest——它在打包时由 `icon_updater` 写进安装器 exe 的 PE 资源，运行期不需要。

## 4. 数据契约收缩表

下表逐字段给出去向。**删除**=连同对应 C++ 逻辑一并移除；**写死**=移入引擎常量/默认；**迁移**=改造成迁移函数表；**保留**=进新 YAML/manifest。

### 4.1 `app`

| 旧字段 | 去向 | 说明 |
|--------|------|------|
| `app.name` | 保留→`productName` | 用户可见产品名 |
| `app.id` | **写死** | 数据目录/注册表键统一用产品名，不再单列 id（需求 §5 数据目录） |
| `app.version` | 保留 | 每次发版必改 |
| `app.directoryName` | **删除** | 不再做隐式路径补齐；GUI 默认目录用 `defaultDir` |
| `app.website` | **写死/删除** | 如仍需展示，引擎写死或随 skin |
| `app.product.icon` | 保留→`icon` | 路径相对 `--config` 解析，写 PE 资源 |
| `app.product.productName/fileVersion/productVersion/companyName/fileDescription` | **删除** | 引擎从 `version`/`publisher`/`productName` 派生（去 `-beta` 后缀满足版本资源纯数字要求，需求 §5） |
| `app.product.copyright` | 保留→`copyright`（可空） | 缺省时引擎用 `publisher + 构建年份` 生成 |
| 新增 `defaultDir` | 保留 | 原 `install.defaultDir` 上提到 `app` |

### 4.2 `package`

| 旧字段 | 去向 |
|--------|------|
| `compression.algorithm` (`xz`/`zstd`/`none`) | 保留（需补 `none`） |
| `compression.level` | 保留 |
| `compression.threads` (`auto`) | **写死**（引擎按 CPU 自动；确需调再提回） |
| `compression.perFileFrames` | **写死**（增量优化策略归引擎） |

### 4.3 `install` —— 整块下沉引擎写死

`requireAdmin / autoStartup / desktopIcon / autoCleanOldInstall / minWindows /
sparseFileThresholdBytes / killProcesses / useMutex / mutexName / installInfo.*`
→ 全部 **写死** 进引擎默认（需求 §5："安装行为默认值…按固定默认处理"）。
注册表持久化路径由引擎内拼接（固定一处注册表 + 一个 `install-state.json`，需求 §5）。

### 4.4 `ui` —— 下沉引擎 + skin

`defaultLanguage / desktopShortcut.* / links / componentSelection.binding.*`
→ **删除**。页面结构与"勾选框↔组件"绑定由 skin 承载，引擎固定加载（需求 §5 UI）。
（单产品已无多组件勾选需求；若保留极少量勾选项，绑定写死在 skin + 引擎，不进 YAML。）

### 4.5 `layout` —— 删除组件体系

`layout.folders` / `layout.components`（embedded/local/download + dependsOn + bat）
→ **删除**。单产品单载荷：所有 payload 视为一份主体内容，落点由引擎按"产品名"约定。
原 local/download 组件的"额外安装动作"能力，由 `hooks.preInstall/postInstall` 替代。

### 4.6 `lifecycle` —— 拆成「写死」与「迁移」

| 旧内容 | 去向 |
|--------|------|
| `lifecycle.registry.onInstall`（Publisher/InstallSource 等） | **写死**：引擎安装时统一写产品注册表与系统卸载入口 |
| `cleanup.onUninstall.*`（processes/registry/shortcuts/startup/paths） | **写死**：卸载主流程按产品名 + 安装清单(manifest)处理；额外固定清理路径写死 |
| `cleanup.onUpgrade.installRoots`（含 Legacy1/2） | **迁移**：旧安装发现逻辑进迁移函数 |
| `cleanup.onUpgrade.registry.legacyKeys` | **迁移**：旧注册表残留清理进对应版本迁移 |
| `cleanup.onUpgrade.uninstallEntries`（Legacy 名单） | **迁移**：旧卸载入口 DisplayName 收尾进迁移 |
| `cleanup.onUpgrade.shortcuts/startup/extraPaths`（Legacy） | **迁移**：旧快捷方式/启动项/残留路径进迁移 |

> 需求 §2.4、§6：跨版本兼容是"读旧状态→判断→分支"的逻辑，**严禁**用 YAML legacy 名单或 bat 承载。

## 5. 新增：迁移函数表（引擎内）

### 5.1 接口（建议 `include/installer/migration/migration.h`）

```cpp
namespace MultiThreadedInstaller::migration {

struct MigrationContext {
    std::string installDir;     // 本次安装目录
    std::string productName;    // 写死的产品名
    std::string fromVersion;    // 已安装版本（注册表读出，可能为空=全新安装）
    std::string toVersion;      // 本次安装版本
    InstallerLogger& log;
};

// 单个迁移：从 < atVersion 升级到 >= atVersion 时执行一次。
struct Migration {
    const char* atVersion;                         // 版本节点，如 "7.0.0"
    bool (*apply)(MigrationContext& ctx);          // 返回 false=失败（按 abort 处理）
};

// 迁移表：按版本升序排列，跟版本走，淘汰随版本删除（需求 §6.4）。
const std::vector<Migration>& Registry();

// 执行：读已装版本，挑出 version > installed 的迁移按序执行，逐条记录完成状态。
bool RunPending(MigrationContext& ctx);

} // namespace
```

### 5.2 执行规则（引擎写死，需求 §6.2）

1. 安装/升级时读注册表中已安装版本 `fromVersion`。
2. 从 `Registry()` 选出 `compareSemanticVersion(m.atVersion, fromVersion) > 0` 的迁移
   （复用 [version_utils.h](include/common/version_utils.h) 的 `compareSemanticVersion`）。
3. 按版本升序依次 `apply`；每条成功后写入"已执行迁移"标记（注册表/`install-state.json`）。
4. 任一迁移返回 false → 视同安装失败 → 回滚（与 hook `abort` 同一回滚路径）。

### 5.3 首批迁移（承接现 YAML legacy 名单）

把 `packager.yaml` 现有的 `SampleDesktopAppLegacy / Legacy1 / Legacy2` 名单改写成代码：

```cpp
// 示例：程序改名但路径未变 → 仅收尾名字残留（需求 §6.3 典型场景）
static bool migrate_7_0_0(MigrationContext& ctx) {
    cleanupLegacyUninstallEntries(ctx, {"SampleDesktopAppLegacy",
                                        "SampleDesktopAppLegacy1",
                                        "SampleDesktopAppLegacy2"});
    deleteLegacyRegistry(ctx, {R"(HKCU\Software\SampleDesktopAppLegacy)",
                               R"(HKLM\Software\SampleDesktopAppLegacy)"});
    removeLegacyShortcuts(ctx, {"Sample Desktop App", "SampleDesktopApp Legacy"});
    removeLegacyStartup(ctx, {"SampleDesktopAppLegacy"});
    removeLegacyPaths(ctx, {"%LocalAppData%\\SampleDesktopAppLegacy",
                            "%AppData%\\SampleDesktopAppLegacy"});
    return true;   // 不动任何当前路径
}
```

> 这些名单作为字面量留在迁移代码里是对的：它们跟版本走，到某版本无用户即可连函数一起删除——
> 不会像 YAML legacy 名单那样越积越多无人敢删（需求 §6.4）。

## 6. 新增：hooks 执行引擎

### 6.1 manifest 携带

```cpp
struct HookManifest {
    bool present = false;
    std::string scriptName;        // 仅日志用，如 pre_install.bat
    std::vector<uint8_t> content;  // 打包期读入内嵌（需求 §4.4）
    std::string args;              // 本次构建特有参数
    enum class OnFailure { Abort, Continue } onFailure = OnFailure::Abort;
    uint32_t timeoutSec = 300;
};
struct PackageHooks { HookManifest preInstall, postInstall; };
```

### 6.2 执行（引擎写死判据，需求 §4.1/4.2/4.3）

```
释放脚本到临时目录（与终端机是否存在原路径无关，§4.4）
设置环境变量：INSTALL_DIR、VERSION（注入，不拼命令行，§4.3）
继承安装器管理员权限运行（脚本内不再 elevate，§4.5）
等待退出，最长 timeoutSec：
  到点未退 → kill → 按失败处理
判据：退出码 0 = 成功；非 0 / 超时 = 失败
失败时按 onFailure：
  abort    → 中止安装并回滚（复用 install_finalize 回滚路径）
  continue → 记日志后继续
```

时序：`preInstall` 在解压前、`postInstall` 在 finalize 后。
可复用现有 [component_launcher.cpp](src/installer/component_launcher.cpp) 的进程启动/超时/kill 能力，
但去掉组件语义，改成两个固定钩子点。

## 8. 一次性切换实施顺序（编译器驱动）

激进切换的安全网是**编译错误**：先改契约层，让所有旧字段消失，编译器把每个引用点标出来逐个改。

1. **契约层先行（必然大面积报错）**
   - 重写 [config_types.h](include/common/config_types.h)：删 `InstallerConfig/UninstallerConfig/
     PackagerInstallConfig/UiConfig/LayoutConfig/LifecycleConfig/*Cleanup*` 等；
     新增 `AppConfig`(精简) / `PackageCompressionConfig`(保留) / `HooksConfig`。
   - 重写 [package_manifest.h](include/common/package_manifest.h)：`PackageManifest` 收窄为
     identity + payload + hooks。
   - 重写 [archive_types.h](include/common/archive_types.h) 的 `ExtendedInstallationMetadata`：
     删掉所有 cleanup/installState/ui/components 字段，只留 identity + payload + hooks。
2. **packager 端补齐解析**
   - [configuration_loader.cpp](src/packager/configuration_loader.cpp) 只解析 app/package/hooks；
     删 [config_parse_collections.cpp](src/packager/config_parse_collections.cpp) 中
     layout/components/cleanup/ui 相关解析；移除 `schemaVersion` 旧值兼容。
   - [configuration_validator.cpp](src/packager/configuration_validator.cpp) 重写校验项。
   - [package_manifest_builder.cpp](src/packager/package_manifest_builder.cpp)：读 hook 脚本内嵌；
     从 version/publisher 派生版本资源喂给 [version_info_updater.cpp](src/packager/version_info_updater.cpp)。
   - codec：[package_manifest_codec.cpp](src/common/package_manifest_codec.cpp) 随结构收窄，`VERSION` 自增。
3. **installer 端**
   - 删除组件流程：`install_plan_builder` / `component_launcher`（改造为 hook runner）/
     `installed_instance_resolver`（legacy 探测下沉迁移）相关分支。
   - 写死默认值：`install_precheck`(minWindows/admin/mutex) / `install_finalize`(注册表/快捷方式/卸载入口)。
   - 接入 hooks 执行（§6）与 migration 执行（§5）到 [install_service.cpp](src/installer/install_service.cpp)。
4. **uninstaller 端**
   - [uninstall_manager.cpp](src/installer/uninstall_manager.cpp) / [upgrade_cleanup.cpp](src/installer/upgrade_cleanup.cpp)：
     删 YAML 驱动的 cleanup，改成按产品名 + 安装清单写死；升级兼容改调 migration。
5. **gui 端**
   - [gui_component_binding.cpp](src/gui/gui_component_binding.cpp)：移除从 metadata 读组件绑定；
     绑定固定加载 skin（§4.4）。其余 page controller 去掉对已删字段的引用。
6. **配置与样例**
   - 用 [docs/new_version/packager.yaml](packager.yaml) 替换根 [packager.yaml](packager.yaml)。
   - 删除 `examples/configurations/*`、`docs/packager-yaml-v3*` 等旧 schema 样例与文档（激进切换）。
   - 提供 `scripts/pre_install.bat`、`scripts/post_install.bat` 样例（遵循 hook 契约）。
7. **构建与冒烟**
   - `cmake --build`，逐个消灭编译错误。
   - 用 `--input/--config/--output` 打一个最小包，跑全新安装 + 升级（验证迁移与 hooks）+ 卸载。

## 9. 风险与验证

| 风险 | 应对 |
|------|------|
| 一次性删字段导致编译错误面巨大 | 这是预期；按 §8 顺序，编译器逐点定位，分模块提交 |
| 已发布旧版本的注册表/路径形态 | 全部由迁移函数承接，先把现 YAML legacy 名单 1:1 转成首批迁移 |
| 组件机制删除后丢功能 | **决策**：office/browser 插件直接移除（不转 hooks、不转迁移），连同 `examples/components/*` 一并删 |
| manifest 二进制不兼容 | **决策**：`Constants::VERSION` 自增；安装器拒绝读旧 manifest（不兼容旧包） |
| hooks 回滚与 abort 一致性 | hook `abort` 与 migration 失败复用同一 `install_finalize` 回滚路径 |

验证用例（对齐需求 §4 契约）：
- hook 退出码 0/非 0/超时三态 × `abort`/`continue` 组合；
- `INSTALL_DIR`/`VERSION` 环境变量在脚本内可读；
- 迁移：fromVersion 为空（全新）/ 低于节点（执行）/ 等于或高于（跳过）；
- 版本资源：`7.0.0-beta1` → FileVersion 纯数字 `7.0.0.0`；copyright 缺省派生。

## 9bis. 运行期阶段实施细则（installer/uninstaller/gui）

> 构建期半边（契约层 + codec + 桥 + packager）已完成并通过编译。本节是运行期半边的落地图，
> 基于对 src/installer 的实际盘点（约 20 文件、235 处旧 metadata 引用）。

### 关键发现：区分「YAML 配置型」与「引擎运行时型」结构

激进切换把下列结构从 **YAML→manifest 流** 中删除，但其中一部分引擎仍需作为**内部运行时类型**
（记录"装了什么、卸载时要撤销什么"），必须**以引擎私有类型重新引入**，不再由 YAML 填充：

| 结构 | 处置 |
|------|------|
| `RegistryEntry`（path/key/value/type） | **重新引入为引擎原语**：registry_utils 写注册表的目标 |
| `NamedCleanupEntry` / `UninstallCleanupRule` / `UninstallEntryCleanup` / `UninstallCleanupConfig` | **重新引入为运行时卸载清单**：install_finalize 记录、写入 install-state，uninstall 时读取执行 |
| install manifest store 相关类型 | **保留**：记录已装文件清单（卸载按清单删） |
| `InstallerCleanupConfig` / `UpgradeCleanupConfig` / `InstalledInstanceDetectConfig` / `InstallStateConfig`（来自 YAML 的清理与探测名单） | **真删**：改由迁移表（升级兼容）+ 引擎写死（卸载） |
| `ComponentConfig` 及组件体系 | **真删**：单产品单载荷 |
| `UiComponentSelectionConfig` / `UiLinkBinding` 等 UI 绑定 | **真删**：skin 固定承载 |

> 建议把重新引入的运行时型放到新头 `include/installer/uninstall_record.h`（引擎私有），
> 与已删的 YAML 配置型彻底分家，避免再次混淆"值/逻辑"。

### 逐文件改法

| 文件 | 旧引用 | 改法 |
|------|--------|------|
| `launch_support.cpp` | appName/appId/appDirectoryName/installDefaultDir/appWebsite/autoStartup/desktopIcon | appName→`appProductName`；appId/appDirectoryName→产品名；installDefaultDir→`appDefaultDir`；website 删；autoStartup/desktopIcon→`EngineDefaults` |

### 新增子系统（净增，不依赖上面解耦）

- **migration**：`include/installer/migration/migration.h` + impl（§5）。首批迁移承接现 YAML 的
