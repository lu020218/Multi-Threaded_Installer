# 打包器流程图

本文档描述当前 `packager.exe` 的主流程。

公开配置已收窄为 `app` / `package` / `hooks` 三块（「值/逻辑各归其位」重构后）。旧 schema（`schemaVersion: 3`、`installer`/`uninstaller`/`components`/`installState` 等）已不再支持，在打包阶段直接失败。配置写法见 [USER_GUIDE](USER_GUIDE.md)。

## 主流程

```mermaid
flowchart TD
    A["启动 packager.exe"] --> B["解析 --input/--config/--output"]
    B --> C{"是否 help"}
    C -->|是| C1["输出帮助并退出"]
    C -->|否| D{"三路径是否完整"}
    D -->|否| D1["报错退出"]
    D -->|是| E["校验 input/config/output 父目录"]
    E --> F["从 config 目录加载 packager.yaml/yml"]
    F --> G["解析 app / package / hooks"]
    G --> H["校验身份、layout、hooks 字段"]
    H --> I["扫描 --input 顶层子目录（按 package.layout 映射 target）"]
    I --> J["按文件夹并行压缩（xz/zstd，可分帧）"]
    J --> K["读取并内嵌 hooks 引用的 pre/post bat"]
    K --> L["PackageManifestBuilder 构建 manifest（identity+payload+hooks）"]
    L --> M["SerializePackageManifest（PMF2 分段编码）"]
    M --> N["注入 PE 资源：版本信息、图标、清单、RES_ZIP、UNINSTALLER_EXE"]
    N --> O["写 installer 模板 + metadata + 压缩载荷 + DataLocator"]
    O --> P["输出自解压 installer.exe"]
```

## 配置加载与校验

```mermaid
flowchart TD
    A["ConfigurationManager.initialize(inputDir, configDir)"] --> B["ConfigurationLoader 加载 packager.yaml/yml"]
    B --> C{"文件存在"}
    C -->|否| C1["配置加载失败"]
    C -->|是| D["YAML 转 JSON"]
    D --> E["解析 app / package / hooks"]
    E --> F["ConfigurationValidator.validate"]
    F --> G{"校验通过"}
    G -->|否| G1["聚合错误到 lastError"]
    G -->|是| H["返回 PackagerConfiguration"]
```

关键规则：
- `app.productName / publisher / version / defaultDir` 必填。
- `package.layout[].source` 必须是 `--input` 下存在的顶层子目录；`target` 支持 `%InstallDir%` 与环境变量。
- `package.layout` 可选；未声明的子目录默认落到 `%InstallDir%\<目录名>`。
- `hooks` 可选；声明时 `path` 相对 `--config` 解析，脚本被读入内嵌；`onFailure ∈ {abort, continue}`。
- 清理规则、注册表、系统卸载入口、安装行为默认值**不在 YAML 中**，由引擎写死；跨版本兼容走引擎迁移表。

## Payload 扫描与 target 固化

```mermaid
flowchart TD
    A["扫描 --input 顶层子目录"] --> B["按 package.layout 查 source→target"]
    B --> C{"在 layout 中声明"}
    C -->|是| D["target = layout.target（展开环境变量）"]
    C -->|否| E["target = %InstallDir%\\<目录名>"]
    D --> F["生成 FolderInfo（folderId/source/target）"]
    E --> F
    F --> G["压缩与 manifest 均使用该 target"]
```

安装器执行时直接读取 manifest 中每个文件夹的 target，不再按目录类型推导落点。

## 压缩流程

```mermaid
flowchart TD
    A["解析压缩策略（algorithm/level）"] --> B["按载荷文件夹创建压缩任务"]
    B --> C{"文件夹数量 > 1"}
    C -->|否| D["顺序压缩"]
    C -->|是| E["多 worker 并行压缩"]
    D --> F["CompressionModule.compressFolder"]
    E --> F
    F --> G{"压缩成功"}
    G -->|否| G1["记录失败并退出"]
    G -->|是| H["生成 CompressionResult"]
    H --> I["含 fileIndex、offset、size、checksum、algorithm、framed"]
```

## Manifest 生成与输出协议

```mermaid
flowchart TD
    A["PackageManifestBuilder.build"] --> B["写 Identity（productName/publisher/version/defaultDir/copyright）"]
    B --> C["写 PayloadManifest（每文件夹 + fileIndex）"]
    C --> D["写 Hooks（pre/post：脚本字节 + onFailure + timeout）"]
    D --> E["SerializePackageManifest（PMF2，3 段 + FNV-1a 校验）"]
    E --> F["写 installer 模板（已注入 PE 资源）"]
    F --> G["写 serialized manifest"]
    G --> H["写压缩载荷块"]
    H --> I["写 DataLocator 与尾部 magic"]
```

最终布局：

```text
[installer 模板 + PE 资源（RES_ZIP / UNINSTALLER_EXE / 版本信息 / 图标 / 清单）]
[分段 package manifest（identity + payload + hooks）]
[压缩载荷块]
[DataLocator]
[end magic]
```

> PE 资源（GUI 皮肤 RES_ZIP、卸载器 UNINSTALLER_EXE、版本信息、图标、requireAdministrator 清单）必须在追加 overlay **之前**由 `EmbedInstallerPeResources` 用 `UpdateResource` 注入到模板文件——`UpdateResource` 会重写 PE 资源节，不能容忍尾部 overlay。

## 模板与资源来源

```mermaid
flowchart TD
    A["packager 所在目录"] --> B["installer / uninstaller 模板 exe"]
    A --> C["DuiLib.dll（可选复制）"]
    D["--config 目录"] --> E["packager.yaml/yml"]
    D --> F["resources/（GUI 皮肤 → RES_ZIP）"]
    D --> G["app.icon（相对路径）"]
    D --> H["scripts/（hooks 引用的 pre/post bat）"]
    I["--input 目录"] --> J["顶层子目录（按 layout 映射 target）"]
```
