# 打包器流程图

本文档按当前代码重新梳理 `packager.exe` 的主流程、配置 schema、压缩与安装包输出协议。

主要入口：
- 打包器入口：[src/packager/main.cpp](../src/packager/main.cpp)
- 配置管理：[src/packager/configuration_manager.cpp](../src/packager/configuration_manager.cpp)
- 配置加载：[src/packager/configuration_loader.cpp](../src/packager/configuration_loader.cpp)
- 配置校验：[src/packager/configuration_validator.cpp](../src/packager/configuration_validator.cpp)
- 元数据生成：[src/packager/metadata_generator.cpp](../src/packager/metadata_generator.cpp)
- 安装包生成：[src/packager/installer_generator.cpp](../src/packager/installer_generator.cpp)

## 主流程

```mermaid
flowchart TD
    A["启动 packager.exe"] --> B["CliSupport.parsePackagerArgs"]
    B --> C{"是否 help"}
    C -->|是| C1["输出帮助并退出"]
    C -->|否| D{"inputPath、configPath 与 outputPath 是否完整"}
    D -->|否| D1["报错缺少必填参数"]
    D -->|是| E["校验输入目录存在且为目录"]
    E --> E1["校验配置目录存在且为目录"]
    E1 --> F["校验输出目录存在"]
    F --> G["ConfigurationManager.initialize(inputDir, configDir)"]
    G --> H{"配置加载与校验成功"}
    H -->|否| H1["输出配置错误并退出"]
    H -->|是| I["确定有效压缩算法、级别、线程预算"]
    I --> J["FolderScanner 扫描输入目录"]
    J --> K{"目录结构有效"}
    K -->|否| K1["报错 Invalid folder structure"]
    K -->|是| L["applyFolderTargets 写入 folder.id 与 targetPath"]
    L --> M["按 folder 粒度压缩"]
    M --> N["PackageManifestBuilder.build"]
    N --> O["SerializePackageManifest"]
    O --> P["准备 installer 模板"]
    P --> Q["InstallerGenerator.generateInstaller"]
    Q --> R["打印 timing summary"]
    R --> S["成功退出"]
```

## 配置加载与校验

```mermaid
flowchart TD
    A[ConfigurationManager.initialize] --> B[ConfigurationLoader.loadConfiguration]
    B --> D{配置目录有 packager.yaml?}
    D -->|是| D1[加载 packager.yaml]
    D -->|否| E{配置目录有 packager.yml?}
    E -->|是| E1[加载 packager.yml]
    E -->|否| F[配置加载失败]
    D1 --> G
    E1 --> G
    G[解析 YAML 为 JSON]
    G --> H{schemaVersion == 2?}
    H -->|否| H1[配置加载失败]
    H -->|是| I[解析 app、package、install、ui、layout、lifecycle]
    I --> J[ValidateLayoutReferences]
    J --> K[应用 install 默认值]
    K --> L[ConfigurationValidator.validate]
    L --> M{校验通过?}
    M -->|否| M1[聚合错误到 lastError]
    M -->|是| N[返回 PackagerConfiguration]
```

## 当前 schema 关键字段

- `schemaVersion` 必须为 `2`。
- `app.name` 与 `app.version` 必填；`app.id` 和 `app.directoryName` 为空时会回退到 `app.name`。
- `package.compression.algorithm` 支持 `xz` 与 `zstd`；压缩级别按算法范围校验。
- `install.defaultDir` 必填；`install.installInfo` 会补默认 registry 路径，但必需字段仍会校验。
- `layout.folders[]` 必须包含 `id`、`source`、`target`，并且 `source` 必须存在。
- `layout.components[]` 可选，支持 `embedded`、`local`、`download` 三类 source。
- `lifecycle.registry.onInstall`、`lifecycle.cleanup.onUpgrade`、`lifecycle.cleanup.onUninstall` 会被写入 metadata，供安装、升级和卸载阶段使用。

## 目录扫描与 target 固化

```mermaid
flowchart TD
    A[FolderScanner.scanInputDirectory] --> B[得到 FolderInfo 列表]
    B --> C[validateFolderStructure]
    C --> D{结构有效?}
    D -->|否| D1[终止打包]
    D -->|是| E[ConfigurationManager.applyFolderTargets]
    E --> F[按 layout folders source 文件夹名匹配扫描结果]
    F --> G[写入 FolderInfo.id]
    G --> H[写入 FolderInfo.targetPath = layout folders target]
    H --> I[后续压缩和 metadata 均使用该 targetPath]
```

当前设计中，打包阶段已经把每个 payload folder 的安装落点写入 `targetPath` 与 `target`。安装器执行时直接读取 metadata，不再根据旧式目录类型或目录名做二次推导。

## 压缩流程

```mermaid
flowchart TD
    A["确定 compressionThreadBudget"] --> B["folderWorkerCount = min(threadBudget, folders.size)"]
    B --> C["perCompressorThreadCount = threadBudget / folderWorkerCount"]
    C --> D{"folderWorkerCount 不大于 1"}
    D -->|是| E["单线程顺序压缩每个 folder"]
    D -->|否| F["创建多个 worker 线程"]
    F --> G["Atomic nextIndex 分发 folder"]
    G --> H["每个 worker 独立 CompressionModule"]
    E --> I["CompressionModule.compressFolder"]
    H --> I
    I --> J{"compressedData 非空"}
    J -->|否| J1["记录失败 folder 并终止"]
    J -->|是| K["保存 CompressionResult"]
    K --> L["记录每个 folder 压缩耗时"]
```

每个 `CompressionResult` 包含压缩数据、压缩前后大小、校验值、算法和文件索引。安装阶段按 tar stream 解压时会记录成功释放的文件，并优先用该列表写入 `install.manifest.json`，避免安装收尾再次递归扫描整个安装目录。

## 元数据生成与序列化

```mermaid
flowchart TD
    A[generateExtendedMetadata] --> B[写 app 与 install 基础信息]
    B --> C[写 installInfo、minWindows、mutex、killProcesses]
    C --> D[写 lifecycle.registry.onInstall]
    D --> E[写 layout.components 与 UI 组件选择配置]
    E --> F[写 ui.links]
    F --> G[写 cleanup.onUninstall]
    G --> H[写 cleanup.onUpgrade]
    H --> I[遍历 CompressionResult 与 FolderInfo]
    I --> J[生成 ExtendedFolderMapping]
    J --> K[写 folderId、folderName、targetPath、target、offset、size、checksum、algorithm、fileIndex]
    K --> L[serializeExtendedMetadata]
    L --> M[写 BinaryMetadata header]
    M --> N[写 extended marker 0x45585444]
    N --> O[写扩展字段与 folder mappings]
    O --> P[回填 metadataSize 与 dataOffset]
```

安装器通过 [src/installer/metadata_parser.cpp](../src/installer/metadata_parser.cpp) 反序列化这些字段，并用 `validateMetadata` 校验版本、magic、folder 数量和 payload 映射。

## 模板准备与资源更新

```mermaid
flowchart TD
    A[准备 InstallerGenerator] --> B{配置了 app.product 图标或版本信息?}
    B -->|否| C[使用默认 installer 模板]
    B -->|是| D[查找默认 installer 模板]
    D --> E[复制为 output 同目录临时模板]
    E --> F[embedInstallerTemplate 指向临时模板]
    F --> G{配置了 icon?}
    G -->|是| G1[UpdateInstallerIcon]
    G -->|否| H[构造 VersionInfoData]
    G1 --> H
    H --> I[UpdateInstallerVersionInfo]
    I --> J[后续 generateInstaller 使用临时模板]
```

图标或版本信息更新失败只产生 warning，不会直接终止打包；模板复制或模板定位失败会终止打包。

## 安装包生成协议

```mermaid
flowchart TD
    A[generateInstaller] --> B[createSelfExtractingExecutable]
    B --> C[加载 installer 模板]
    C --> D[定位 packager 所在目录]
    D --> E[检查 resources 目录存在]
    E --> F[加载 uninstaller 模板]
    F --> G[AppendEmbeddedResources 到 uninstaller 模板]
    G --> H[AppendEmbeddedResources 到 installer 模板并嵌入 uninstaller 模板]
    H --> I[创建输出 exe]
    I --> J[写 installerTemplate bytes]
    J --> K[写 serialized metadata]
    K --> L[顺序写入所有 compressedData]
    L --> M[写 DataLocator]
    M --> N[写尾部 MAGIC_NUMBER]
    N --> O[设置可执行权限]
    O --> P[复制运行时依赖 DuiLib.dll 如果存在]
```

最终自解压 exe 的二进制布局：

```text
[installer template + embedded UI resources + embedded uninstaller]
[serialized metadata]
[compressed folder payload blocks]
[DataLocator]
[end magic]
```

`DataLocator` 记录 metadata 和 payload 的偏移与大小。安装器运行时通过尾部 magic 反向定位该结构，然后读取 metadata 与 payload。

## 关键规则

- 配置文件只从 `--config` 指定目录读取 `packager.yaml` 或 `packager.yml`。
- 当前正式 schema 为 v2；旧式目录类型配置不再参与主流程。
- `layout.folders[].target` 是安装器落点的唯一来源之一，会被固化进 metadata。
- 组件依赖、组件引用的 folder id、download SHA256、local installer 路径约束都会在打包阶段校验。
- 多 folder 压缩时按 folder 粒度并行，每个 worker 拥有独立 `CompressionModule`。
- 生成 installer 时要求 `--config` 指定目录下的 `resources` 目录存在，并强制把 UI 资源嵌入 installer 和 uninstaller 模板。
- 生成后的 installer 会尝试复制 `DuiLib.dll`；如果静态链接或文件不存在，仅输出提示。
- 打包器会输出阶段耗时和最慢 folder 压缩耗时，便于定位性能瓶颈。
